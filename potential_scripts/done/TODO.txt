### 4. Tool Gateway (gateway.py)

Class `ToolGateway`:
- Wraps every tool call: snapshot PostgreSQL state BEFORE, execute, 
  snapshot AFTER, compute delta, write BehavioralRecord to 
  halluci_audit table
- BehavioralRecord fields: step_id, trajectory_id, timestamp, 
  tool_name, parameters, return_value, state_before, state_after, 
  state_delta, claim_pre, claim_post
- Method `execute(tool_name, params, claim_pre=None) -> dict`
- Method `set_claim_post(step_id, claim_post)`
- PostgreSQL connection to localhost:5432, db=odoo_research
- The prompt’s list of 20 tools is a starting point. Verify against Odoo documentation and your research objectives. If you intend to measure misalignment in other modules (e.g., purchase orders, manufacturing), expand the list accordingly. Having a comprehensive list allows the agent to choose the correct tool rather than hallucinating unsupported actions.

### 5. Claim extraction

In harness.py, after each agent turn, extract claims from the text:
- `claim_pre`: the LAST claim before a tool call (look backwards for 
  Intention/Constraint typed statements: "I will...", "I am going to...",
  "I won't...")
- `claim_post`: the FIRST claim after a tool call result (look forwards 
  for Completion/State statements: "I have...", "The [X] has been...", 
  "Successfully...")

Use a simple regex + heuristic first (mark with TODO for LLM judge later).

### 6. Experiment harness (harness.py)

`ExperimentRunner` class:
- `run_experiment(agent_name, model_name, task_prompt, knowledge_level,
  api_key, n_runs=1) -> ExperimentResult`
- Manages the full multi-turn loop until task completion or max_steps=15
- After each turn: extract claim_pre/post, call gateway.execute for

- Saves results to experiments/runs/{timestamp}_{agent}_{task}.json
- ExperimentResult: { trajectory_id, agent, model, task, knowledge_level,

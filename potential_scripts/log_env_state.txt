1. PostgreSQL 后端 = BtB_t
Bt​ 自动产生

每一个 Odoo 业务操作最终都落到 PostgreSQL 的一次 INSERT / UPDATE / DELETE 上。你的 env_state_delta 不需要额外开发——直接查表就是。
sql-- 查看某个 stock_move 记录的变更历史
SELECT *
FROM stock_move
WHERE write_date > NOW() - INTERVAL '10 minutes'
ORDER BY write_date DESC;

-- 或者开启 pg_audit 插件，得到完整的 WAL-level 操作日志


2. 统一 ORM 模型 = tool_name 和 parameters 天然结构化
Odoo 所有外部操作都通过 JSON-RPC 的 execute_kw 方法调用，格式是固定的：
# Agent 调用一个 "处理退款" 工具，底层是：
models.execute_kw(db, uid, password,
    'pos.order',      # model name = tool_name
    'refund',         # method = action type  
    [[order_id]],     # args = parameters
    {'reason': 'damaged item'}  # kwargs = key parameters
)
这个结构正好对应你 Definition 2 的 verifiability score 的评估：tool_name 是 action type，kwargs 是 key parameters，v(c) = 1 的条件完全可以自动判断。

Bt​ 记录开箱即用
